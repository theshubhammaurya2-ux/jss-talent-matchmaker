# Role 1 → Role 5 integration handoff

**From:** JD Analytics (Role 1)
**To:** Skill Matching (Role 5)

## Input to Role 1
A job description PDF or DOCX uploaded as the `file` field.

## Output to Role 5
A JSON object shaped as:

```json
{
  "source_type": "jd",
  "source_file": "Google LLC - Software Engineer.pdf",
  "company": "Google LLC",
  "role": "Software Engineer (SWE)",
  "skills": [
    {
      "skill_name": "Data structures and algorithms",
      "category_code": "DSA",
      "evidence": "Strong grasp of data structures and algorithms",
      "confidence": "high"
    }
  ]
}
```

This is an illustrative, partial example. Real extraction is made by the configured LLM; it should not be represented as an output actually generated by the model unless tested.

## API

Once Role 1 backend is running at `http://localhost:8000`:

- `POST /api/jd/analyze`: multipart form field `file` → structured JSON.
- `POST /api/jd/extract-text`: multipart form field `file` → raw text.
- `GET /health`: readiness status.

## Important agreements before integration

1. Use the case-sensitive category codes from the brief: `COD`, `DSA`, `OOD`, `APTI`, `COMM`, `AI`, `CLOUD`, `SQL`, `SWE`, `SYSD`, `NETW`, `OS`, `OTHER`.
2. `confidence` is `high`, `medium`, or `low`; it is not a numeric weight.
3. The brief does not define an optional-vs-required skill flag. For now extraction excludes items appearing **only** in "Nice to Have". If you want different weighting, agree on a schema extension as a team.
4. Do not treat a low-confidence extracted skill as equally reliable without discussing scoring rules.
5. Evidence is sourced from the original JD. The implementation rejects unsupported evidence phrases and rejects empty skill lists.
6. Keys and naming should be locked before the team codes in parallel.

## Minimal test

1. Send Google SWE JD to `/api/jd/analyze`.
2. Confirm skill list includes DSA, operating systems, networking, object-oriented design, system design, software engineering, and communication signals.
3. Send Google Data Scientist JD and check that SQL, AI/ML, analytical reasoning, communication are emphasized instead.
4. Check no fake skill requirement is introduced from benefits or product names.
5. Try 3 real JDs per milestone checklist; Role 5 should be able to use their `skills` arrays directly.
